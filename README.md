# Meeting Recorder

macOS上でマイクとシステム音声をローカル録音し、多言語文字起こし、声ごとの話者分類、全文ログ、議事録を作成するMVPです。

## 特徴

- ScreenCaptureKitでシステム音声を直接取得。Zoomや既定の出力デバイス設定は変更しません。
- 任意のマイクをAVCaptureDeviceから直接選択。システムの既定入力は変更しません。
- 音声を5分単位のM4Aへ分割し、録音中も`session.json`を更新します。
- 録音項目の名前変更と、macOSのゴミ箱へ移動する安全な削除。
- 録音詳細で元音声を連続再生・一時停止・位置移動。マイクのみ、システム音声のみ、両方を選択できます。
- whisper.cppとMetal GPUによる`large-v3`の精度優先文字起こし（Apple Silicon）。言語・専門用語ヒント・認識対象の音声を選択できます。CPU方式のfaster-whisperも選択可能です。
- マイクとシステム音声を別々に認識し、時刻順に統合。重なっている長い同一発言だけを重複除去し、音声別の認識結果も保持します。
- 過去の録音の文字起こしをやり直し、以前のログと議事録を`history/`へ保存。
- pyannote.audioによる声ベースの話者A/B/C分類。
- Ollamaと`qwen3.5:9b`による、完全ローカルの構造化議事録生成。長いログは分割して事実を抽出し、最後に統合します。
- 録音・文字起こし・要約データはすべてMac内へ保存し、外部サービスへ送信しません。

## 必要環境

- macOS 13以上（macOS 15推奨）
- Xcode 16またはSwift 6
- ffmpeg
- Python 3.10〜3.13（音声処理用。Python 3.12推奨）
- GPU版はApple SiliconのMac。Intel Macでは設定で「CPU（従来方式）」を選択してください。
- Whisper `large-v3`（各エンジンの初回に約3GBをダウンロード。GPU版はF16・非量子化モデル）
- Ollamaと`qwen3.5:9b`（要約用、約7GBの空き容量を推奨）
- 話者分類にはHugging Faceで`pyannote/speaker-diarization-community-1`の利用条件への同意とアクセストークンが必要です。

## セットアップ

```zsh
brew install ffmpeg python@3.12 ollama
brew services start ollama
ollama pull qwen3.5:9b
./setup_runtime.sh
./build_app.sh
open 'dist/Meeting Recorder.app'
```

初回録音時にmacOSからマイクと画面収録の許可を求められます。画面収録の権限はシステム音声取得に必要ですが、このアプリは映像をファイルへ保存しません。

話者分類を使う場合は、アプリの「設定」でHugging Faceトークンを登録します。トークンはmacOSキーチェーンへ保存されます。

Ollamaの状態は次のコマンドで確認できます。

```zsh
ollama list
curl http://127.0.0.1:11434/api/version
```

`qwen3.5:9b`以外を使う場合は、アプリの「設定」でモデル名を変更してください。指定モデルが見つからない場合は、インストール済みの対応モデルを自動選択します。

Apple Siliconでは`setup_runtime.sh`がGPU用エンジンもビルドします。既存ランタイムから更新する場合は`./setup_gpu_runtime.sh`を実行してください。CMakeはアプリ専用Python環境へ、固定版whisper.cpp（v1.9.4）は`~/Library/Application Support/MeetingRecorder/runtime/`へ導入します。他のソフトが使うHomebrewパッケージは変更しません。GPU用モデルはHugging Faceキャッシュへ保存され、既存のCPU用モデルとは別形式です。

## 文字起こしの品質設定

設定のWhisperモデルは`large-v3`が精度優先の標準です。速度とのバランスを重視する場合は`large-v3-turbo`を指定できます。日本語の会議は「日本語」、他言語を含む会議は「自動検出（多言語）」を選びます。「専門用語・人名のヒント」には会議で実際に使う正しい表記を入力します。

標準エンジンは「Metal GPU」です。Metalの実使用を処理ログで確認し、GPUを使えなかった場合はエラーにします。無断で遅いCPUへ切り替えません。長時間音声は前後10秒の文脈を含む10分窓で処理し、メモリ使用を抑えます。言語の自動検出は窓単位です。GPUの利用で他の映像ソフトと負荷を共有する点に注意してください。音声デバイス設定は変更しません。

マイクとシステム音声は標準で別々に認識します。Zoomの相手音声をマイクでも拾う場合は、イヤホンを使用すると二重録音を抑えられます。同じ人の声でも二つの音声経路で表現が異なる場合、重複発言が残ることがあります。不要な経路は「マイクのみ」「システム音声のみ」で除外できます。

過去の録音へ新しい設定を適用するには「文字起こしをやり直す」を押します。「議事録を作成」は既存の全文ログを使って要約だけを更新します。再認識が成功した後、以前のログ・議事録・認識設定を会議フォルダ内の`history/日時/`へ退避します。音声認識に失敗した場合は以前のログを保持し、要約に失敗しても新しい全文ログと以前のバックアップは残ります。

処理中は「処理を中止」で停止できます。アプリ終了時にも実行中の処理を停止し、GPU用の子プロセスも終了します。途中の認識進捗は保存しません。音声と完成済みログ、すでに作られた履歴は保持します。

固有名詞、聞き取りにくい発話、同時発話は誤認識が残る場合があります。`transcription.json`に認識モデル、エンジン、GPU使用確認、処理時間、言語、ヒント、重複除去数を記録します。低信頼度の発言数はCPU版のみ計測し、GPU版では`null`です。同じモデルでもエンジンによって結果が異なることがあります。発言の正しさは元音声で確認してください。

## 保存場所

各会議は次の場所へ独立して保存されます。

```text
~/Library/Application Support/MeetingRecorder/Sessions/
```

各セッションには、音声チャンク、`session.json`、`transcript.md`、`transcript.json`、`minutes.md`が入ります。新しい文字起こしでは、音声別の未統合結果`transcript.sources.json`と認識設定`transcription.json`も保存します。

## 現時点の制約

- 録音後に文字起こしを実行する方式です。ライブ字幕はまだありません。
- 複数ディスプレイ環境では先頭ディスプレイのシステム音声フィルターを使用します。音声はmacOS全体から取得されます。
- ローカルにApple Development証明書があれば自動的に安定署名し、なければアドホック署名します。一般配布にはDeveloper ID署名と公証が必要です。

## トラブルシューティング

システム音声の権限を拒否した場合は、次を実行してからアプリを開き直してください。

```zsh
tccutil reset ScreenCapture local.meeting-recorder
```

その後、macOSの「プライバシーとセキュリティ」→「画面とシステムオーディオの収録」でMeeting Recorderを許可します。
